# Decision Log

Every locked decision and the reason behind it. Newest decisions at the bottom of each
section.

## Project

| Decision | Why |
|---|---|
| Name **FutureBlitz**, extension `.fb` | revives an earlier dead project, this time to finish |
| **No Blitz3D source compatibility** | frees the design; old code is translated by migrator + AI instead |
| A **sibling language**, not a dialect; nothing ugly inherited from Blitz | approachable BASIC feel without the baggage |
| **No "modern vs classic" split** anywhere | it's a new language and engine; every feature is first-class |
| MIT license | broad adoption |
| Language, compiler, tooling first; engine after | the engine is built on a finished language |

## Lexical and syntax

| Decision | Why |
|---|---|
| Remove type suffixes (`%`, `#`, `$`) | pointless with real types and an IDE/LSP |
| Case-sensitive, PascalCase keywords; a miscased keyword gets a fix-it on syntax errors | simpler tooling; `if` stays a valid identifier |
| `//` and `/* */` comments | frees `'` for character literals |
| Every block ends with `End <Kind>` | consistency; no `Wend`/`Next`/`EndIf` |
| Parentheses required on every call | removes Blitz's command-call ambiguity |
| Top-level code is the only entry point; `Main` is an ordinary name | keeps Blitz's script feel; one way to start a program |
| No `Goto`/`Gosub` | |
| String escapes, interpolation, raw and multi-line strings | Blitz had none |
| Lines end at `\n`, `\r\n`, or `\r`; leading BOM ignored | same line rule as the LSP |
| Contextual keywords: `Get`, `Set`, `Step`, `Lib`, `From`, `Weak` | lets names like `Set<T>` and `.Step(dt)` exist |
| `Func` and `Callback` both reserved | both build function types; uniform type parsing |
| ASCII-only identifiers in v0 | simple lexer; Unicode can be added later without breaking code |
| `\xHH` limited to ASCII; `\u{...}` must be a scalar value | strings are always valid UTF-8 |
| Decimal literals need digits on both sides of `.` | `1..3` and `a?.b` lex unambiguously |
| Newlines end statements inside block bodies, even within brackets | block lambdas work as call arguments |
| Continuation after binary operators, `=`, compound assignment, `,`, `=>` | long expressions and signatures split naturally |
| Multi-line strings strip the closing `"""`'s indentation | unambiguous with mixed tabs and spaces |
| `#Else` added to conditional compilation | the obvious missing branch |
| A block comment counts as a space, even across lines | comments never change how code parses |
| An interpolation in a single-line string ends on the same line | the string itself is one line |
| Spaces or tabs may follow an opening `"""` | invisible trailing whitespace shouldn't be an error |
| Lines that start inside an interpolation skip the indentation check | they're code, not string text |
| Only calls, assignments, and `++`/`--` can be statements | a bare expression does nothing, so it's almost always a mistake |
| Trailing commas allowed in bracketed lists | multi-line lists are easier to edit and diff |
| Single-line `If ... Then ... Else ...`; no `ElseIf`, no block statements | one-liners stay one line; anything bigger is a block |
| A label must come right before a loop | labels only exist for `Break` and `Continue` |
| `>>`, `As?`, and `T?` are written without spaces | tells shifts from nested generics and `T?` from the ternary |
| Lambdas are always written with `Function` (`=> expr` or a block); no `() =>` | one way to write a function |
| `Func(A, B): R`; a `?` or `[]` after it belongs to the return type, so `(Func(): Int)?` needs parentheses | the return type reads like any other type annotation |
| A lambda's parameter types and return type come from the Func expected where it is, unless it writes them | `list.Filter(Function(x) => x > 0)` stays short |

## Operators

| Decision | Why |
|---|---|
| C-style operators for arithmetic, comparison, logical, bitwise | no word operators like `And`/`Or`/`Not`/`Mod` |
| `Operator +(a: T, b: T): T` in a Struct or Class: a Static function named by its operator, taking a value of its type | operators are found through their operands' types, with ordinary overloading |
| `!=` is always `!(a == b)`; `&&`, `\|\|`, `??`, `?:`, `Is`, and `As` can't be overloaded | the operators that decide control flow or types keep one meaning |
| `x op= y` uses `op`; a type's `Operator ==` is used by every `==` on it, inside Structs, tuples, `T?`, and `Contains` too | one definition of equality per type |
| An Operator has no ByRef or default parameters, no type parameters of its own, and doesn't throw | an operator reads like arithmetic, which has no hidden effects |
| Split `=` (assignment) and `==` (comparison) | BASIC's dual-use `=` is ambiguous |
| Assignment is a statement; `++`/`--` are statements | avoids `x = i++` trickery |
| Ternary `? :` | C-style |
| `Is`, `As`, `As?` remain words | C has no equivalent |

## Types and semantics

| Decision | Why |
|---|---|
| Sized integers, floats, `Bool`, math types built in | Blitz had only Int/Float/String |
| Any variable with an initializer may omit its type; without one it needs a type; parameters and return types are always annotated; definite assignment enforced | safety without verbosity |
| Non-null by default, `T?`, flow narrowing | eliminates null crashes |
| Only lossless implicit conversions | |
| `Class` (reference) + `Struct` (value); `Class` replaces `Type` | `Type` was a confusing keyword |
| No per-type global lists | use collections / `Pool<T>` |
| Single inheritance + interfaces with default methods | |
| Visibility: `Private` (default, file), `Protected`, `Package`, `Public` | |
| Statics on classes and structs | |
| A Static Field is a Global named after its type, initialized with the Globals in source order; a Static Method has no Self and isn't virtual | statics are module data and functions in a type's namespace |
| `ReadOnly` goes before Fields only: they change only in their Class's `New`, through Self; a Global that never changes is a `Const` | `Const` already holds values made at run time, objects included |
| A ReadOnly Field can be assigned more than once in `New` | the point is that nothing changes it afterwards, which needs no flow analysis |
| A Property's Get and Set are Methods; a Class's are virtual, and `Override Property` replaces them | Properties fit the existing Method tables, and overriding works the same way |
| A Struct's Set changes the variable, like a ByRef Method; a Struct-typed Property gives a copy, so changing part of it is an error | a change that would land on a copy is always a mistake |
| `T[]` and collections are references; `T[N]` is a value; `.Clone()` copies | |
| Struct `==` field-wise; class `==` via `Equatable` or identity; `RefEquals` | |
| Overflow traps in debug, wraps in release; explicit wrapping/checked ops | |
| Strings: no `s[i]`; `.Chars` and `.Bytes` | UTF-8 correctness |
| Integer literals convert to any numeric type that holds their value; decimal literals only to `Float`/`Double` | `Vec3(0, 1, 0)` works without loosening the lossless-only rule |
| Mixed numeric operands: one side must widen losslessly to the other's type | the lossless-only rule, applied to operators |
| Overloads: an exact match beats a lossless conversion; anything else is ambiguous | predictable resolution |
| `For` declares its own loop-scoped variables, which can't be assigned inside the loop | nothing leaks out; nothing changes the count by accident |
| Functions, `Global`s, and top-level `Const`s are file-wide; top-level `Local`s belong to top-level code; no redeclaring, no local hiding a local | declare-anywhere functions like Blitz, without surprise shadowing |
| `Global`s and top-level `Const`s initialize in source order before other top-level code, using only names declared above | deterministic startup; no read before initialization |
| A function that an initializer calls and that uses a Global main hasn't set yet panics there, through a flag main sets after each initializer (MIR `ready_t`); release builds check only a Global whose zero holds a null object, and read any other as its zero; a lambda in an initializer may use a later Global whose type is written (M5 final review) | the call can go through function values, Interfaces, and overrides, which no compile-time walk sees without refusing code that's fine; a null object would crash, which a check turns into a clear panic, as Assert's does, while any other zero is a value of its type, as wrapped overflow is, so release builds don't pay for that check on every use; a lambda runs later, and one Global's type can't depend on code that reads it |
| A struct method sees `Self` read-only; a `ByRef Method` can change it, and needs something assignable to be called on | parameters are read-only, and `Self` is a parameter; changes are visible in the declaration |
| Every struct gets a constructor whose parameters are its fields, in order, with their defaults; declaring `New` replaces it | records need no boilerplate; `Vec3(0, 1, 0)` and `Particle(life: 1.0)` both work |
| A field's default must be known at compile time, like a parameter's; struct defaults are checked in source order with the Globals | a field default is a default of the generated constructor |
| A field without a type takes its default's, so code above its Struct can't use that field | the type isn't known until the default is checked |
| A Struct is stored inline, so it can't contain itself, directly or through other Structs | it would have no size; use a class reference (M2 step 3) |
| A field, like a variable, can be passed `ByRef`; two `ByRef` arguments that overlap (`p` and `p.x`) are an error | the same rule as passing one variable twice |
| Changing a field of a `Local` reads the rest of it, so the `Local` must be assigned first | definite assignment tracks whole variables |
| A Struct or Class goes in a string through `Printable`'s `ToString` | its text is a choice the type makes |
| A Class without a `New` gets one without parameters | an object always starts from its field defaults |
| A Class's Methods can always change its fields; `ByRef Method` is only for Structs | `Self` is a reference, so there's no copy to protect |
| An object's fields change through any reference to it, even a read-only parameter or `Const`; a Class's `Self` can't be replaced | read-only covers the reference, not the object |
| Class `==` compares identity unless the Class has an Operator `==`; `RefEquals` always compares identity | identity is the equality every object has |
| Methods are virtual unless `Final`; `Override` must match the parameter types, `ByRef`, and return type exactly | one rule for what overrides what |
| Every Class's `Destroy` runs, the most derived first, and none overrides another | each Class cleans up its own fields |
| A Class's `New` runs the base's New once, with `Super.New(...)` among its own statements, outside any block, or the base's `New` that takes no arguments; before it, New assigns its own Fields that have no zero, by name, and may read the ones it has assigned, but can't use Self, inherited members, lambdas that capture Self, or Return; a Throw there discards the object without its Destroy (Swift's rule, phase 1's A3-1) | the object is set up from the base down, and a base New's virtual calls never see one of the Class's Fields unassigned; reading an assigned Field reaches no override |
| A Class without a `New` that extends another takes the parameters of each of its base's News, and passes them on | an error Class is two lines, and fields with defaults don't need a New |
| An object's fields start with its base Class's, and its Class's info has a Method table after `fb_class_t` | inherited fields and overrides cost no lookups |
| `As` to a subclass, and from a `T?` to a `T`, checks at run time and panics with the Class it found; `As?` gives `Null`; unrelated Classes are a compile error | casts that can't work are caught early, and ones that fail at run time say why |
| Two Classes meet at the nearest one both extend: `True ? rect : circle` is a `Shape` | the ternary works across a hierarchy |
| `Is` doesn't narrow; `Case e As T` binds the object as a `T` | narrowing stays about `Null`; a type match names the result |
| A `T[]` is an object whose elements are in a buffer of their own, with a Class named like `Int32[]` | it grows without moving, and leak reports name arrays |
| A `T[]`'s `Count` is an `Int`; its Methods are `Add`, `Insert`, `RemoveAt`, `Clear`, `Contains`, and `Clone` | the collection vocabulary, starting small |
| A `T[]` has no zero; `[]` as a default gives each use a new array | non-null by default, without a shared mutable default |
| `T[]` is invariant: a `B[]` isn't an `A[]` | adding an `A` to a `B[]` would break it |
| An array's `==` compares its elements, when they have `==`; `RefEquals` tells `T[]`s apart | the same equality a Struct's fields have |
| A fixed array starts at zero, so a `Local` of one is ready when declared; sizes are known at compile time | declaring then filling a grid is the common case |
| An array element can't be passed `ByRef`, and a `ByRef Method` can't change a `T[]`'s element in place | the buffer moves when the array grows |
| `For ... In` holds the array and reads `Count` before each pass; its variables are read-only copies | removing during a loop can't go past the end |
| Enum values are known at compile time and can use the members above; names and values don't repeat | a value names one member, so `Select` and strings are unambiguous |
| An Enum compares with `==` and `!=` only; `@Flags` adds `\| & ^ ~` and `Has`; `As` converts to and from integers | an Enum isn't a number, but a set of flags is a set of bits |
| `As` to an Enum without `@Flags` checks that the integer is one of its values | every value of a plain Enum is a member, so `Select` can be exhaustive |
| An Enum's zero is its first member, or no flags | fields and arrays of Enums start at a real value |
| A string shows an Enum value's name; a `@Flags` one that isn't a member shows its flags | debugging output reads as source |
| `@Flags` is the one attribute in M2 | the rest come with compile-time features |
| A tuple `(A, B)` is a value like a Struct without a name; its elements are `.0`, `.1`, and so on | multiple returns and pairs need no declared Struct; numbered as in Swift and Rust |
| `Local lo, hi = t` takes a tuple apart, with a name for every element and `_` to skip one; only a Local can | each name takes its element's type, and the tuple's whole shape is checked |
| `a, b = (b, a)` makes the whole value before assigning any target, then assigns them from the left | a swap works, in the order Python uses |
| A tuple literal converts element by element to the tuple its context expects; another tuple value converts only to its own type or its `T?` | `Return (lo, hi)` works for a `(Long, Long)`, and whole tuples don't convert behind the scenes |
| Tuples compare and show in strings element by element, as `(1, a)` | they're plain values with nothing else to show, and printing pairs is common |
| A tuple can't hold a `Weak<T>` | a check can't narrow what it reads; a Weak belongs in an object's field |
| A Func can't throw; a lambda catches the errors of what it calls, and Functions that throw aren't values | a caller of a function value can't know what it throws until interfaces and generics can say |
| Inside a lambda, a captured `Local` isn't narrowed; outside, a `Local` that a lambda assigns stops narrowing once the lambda exists | any call could run the lambda between a check and a use |
| `Defer` runs one call, assignment, `++`/`--`, or one-line `If`, which can't leave the block | a way out can't jump somewhere else halfway through its cleanup |
| A Defer's expressions are evaluated when it runs, as in Swift; `Return`'s value is computed first | it cleans up what's there at the exit, and can't change the result behind the `Return` |
| A block's Defers and the releases of its variables run together, the last first | what's declared before a Defer is still alive when it runs |
| A panic doesn't run Defers | a panic ends the program, and cleanup in a broken state could hide the first failure |
| A Class, or a Struct holding one, has no zero: a `Global` of one needs a value, a Struct's generated constructor requires the field, and every `New` assigns it on every path before reading it or using `Self` | a reference that can't be `Null` must point at an object before anything reads it |
| `Null` takes the `T?` its context expects; a `T` or `T?` converts to a `U?` when the `T` converts to the `U` | `Null` alone has no type |
| Null checks narrow a Local, a Const, or a parameter that isn't `ByRef`, until it's assigned a `T?` or passed `ByRef`; a loop that changes it can't use a check from before the loop; a Global or field needs a Local copy | anything a call could change can't stay narrowed |
| `a?.b` is a `B?` on its own: a chain writes `a?.b?.c` | each `?.` is one visible check |
| `?.`, `??`, and `== Null` on something that can't be `Null` are warnings | the code works; the check is wasted |
| Two `T?` values are equal when both are `Null` or both hold equal values; a `T?` can't be interpolated without `??` | equality follows the `T`'s, and `Null` has no text |
| A `String?`, or a `T?` of a Class, is a pointer that's null for `Null`; any other `T?` is a flag and the `T`, which holds the `T`'s zero while it's `Null` | references cost nothing extra, and releasing a `Null` is always safe |
| A function with a return type returns on every path; one without can't return a value | catches missing returns |
| `Select`: case values known at compile time and of the subject's type; ranges on integers; no duplicates | clear matching and cheap code |
| Parameters are read-only; default values must be known at compile time | no surprise changes; defaults cost nothing at the call |
| `ByRef` parameters, written at the call too (`Swap(ByRef x, ByRef y)`); only assignable, already-assigned variables of the exact type; never the same one twice | changing the caller's variable is visible where it happens |
| A bare `Return` in top-level code ends the program | an early exit for scripts |
| `As` wraps between integers; float to integer truncates and errors (or panics) out of range | explicit casts do what they say; nothing silently becomes garbage |
| Bitwise operators work on integers only; `Bool As <integer>` gives `1` or `0` | no bit tricks on `Bool`, but an explicit way to count with one |
| A `Global` without an initializer starts at zero, `False`, or `""` | assignment can't be tracked across functions; Blitz did the same |
| Literals with no expected type are `Int`, or `Float` when a decimal is among them | `1 + 0.5` does what it looks like |
| A literal argument matches its default type exactly and other types it fits by conversion | keeps overload resolution two-tier |
| A `For` with a literal start counts in the end's type | `For i = 0 Until n` works for any integer `n` |
| `Until` can't see the `Repeat` body's `Local`s | the condition is outside the block |
| `While True` and friends count as never ending | a function ending in a main loop needs no dead `Return` |
| Named functions only at the top level | lambdas cover nested functions |
| Numbers in strings print in the shortest form that reads back exactly | `0.1` prints as `0.1` |
| Out-of-range shifts panic in debug and are masked in release; division by zero and out-of-range float-to-integer `As` always panic | like overflow, but never undefined behavior |
| `For` evaluates start, end, and step once, never steps past the end, and panics on a run-time `Step` of 0 | no surprise wraparound or endless loops |
| Panics exit with code 101 | tests can tell a panic from a normal exit |

## Memory

| Decision | Why |
|---|---|
| **Refcounting** (not tracing GC) | deterministic, no frame hitches |
| `Weak<T>`; debug cycle detector | break cycles |
| `Destroy()` runs when refcount hits 0 | deterministic cleanup |
| `Destroy` is `Method Destroy()`, without parameters or a result; it runs before the fields are released, can't be called, and panics if it keeps a reference to its object | the object is about to be freed, so nothing may hold on to it |
| An object starts with a header: its counts and its Class's info (name, size, destroy, release, visit, count); the leak report names Classes | leaks are easy to find, and the runtime needs no type tables |
| A `Weak<T>` is assigned a `T`; reading it gives a `T?` that's `Null` once the object is gone | `parent?.name` works with the null operators already in the language |
| Reading a `Weak<T>` makes a strong reference, which a check can't narrow | the object can't go away while it's used, but it can between reads |
| An object's header has a 32-bit refcount and a 32-bit weak count; memory waits for the last Weak, the object doesn't | Weak needs no side table, and the header stays 16 bytes |
| `fb_class_t` has separate destroy, release, and visit functions | a `New` that threw skips `Destroy()`, and the cycle detector walks references |
| Debug builds track every object and report each leaked cycle by its fields; release builds only count leaks | finding a cycle is the hard part of fixing a leak, and release builds shouldn't pay for it |
| Closures capture by reference; C++-style capture lists `[Weak Self]`; compiler warns on strong `Self` capture stored in a field | prevent refcount cycles |
| A function value is a reference to a closure: an object of a Class made for its lambda, named like "Function at main.fb:3:12", with a field for each capture and its code in the Method table | closures are counted and freed like any object, and leak reports name them and the cycles through them |
| A captured `Local` lives in a `Cell<T>` object for its whole life; what can't change (parameters, loop variables, Consts, Self) is copied | sharing a variable needs somewhere both sides can reach, and copies cost nothing; each `For` pass gets its own variable |
| A Function used by name becomes a new closure object each time, whose code calls it | one way to call every function value; a static object for closures without captures can come later |
| Pointers only in `Unsafe` | normal code never needs them |

## Generics

| Decision | Why |
|---|---|
| `<T>` syntax | |
| **Both** inline constraints and `Where`; formatter enforces which | inline for simple cases, `Where` for everything else (conditional methods/conformance, relations) |
| Monomorphization | native speed |
| Invariant generics | avoids soundness bugs |
| Const generics | `T[W, H]`, fixed-size math |
| C#-style `<` disambiguation | |
| A generic body is checked once with opaque type parameters, then lowered once per set of type arguments | errors point at the generic code, and each instance is ordinary code |
| Type arguments are inferred from the arguments' types, then literals, then lambdas, then the type expected | each step uses what the earlier ones learned, so `Map(xs, Function(x) => ...)` needs nothing written |
| A non-generic overload beats a generic one that fits as well | the specific function is the one meant |
| Overloads may differ by their count of type parameters, as in C#: a call that writes type arguments can't pick one with fewer, one that writes none takes a generic one only where its arguments tell its type arguments, a function value picks the same way, and a Class's Method of another count is an overload beside an inherited one or an Interface's default, not its Override (step 19) | the user's call, 2026-10-27: `Json.Read(text)` gives a Value and `Json.Read<T>(text)` a T |
| Generic Methods aren't in the Method table, so they can't be Abstract or Override | each set of type arguments is a different function, which a table can't hold ahead of time |
| `T?` with a nullable `T` is a `T??`, a type of its own that can be written, with a flag of its own around the `T?` (M5 final review, which changed "is that type") | generic code's Null for "none", as Map.Get, Find, an Iterator's Next, and a Channel's Receive give, has to stay apart from a Null it holds, or For ... In stops at a stored Null; Swift does the same |
| A `T?` converts to a `T??` as a value, and to a `U?` of its own depth as its T does; narrowing, `??`, and `?.` take off one `T?` at a time, and a narrowed variable reads as the `T?` inside | each level means its own Null, so one conversion or check can't stand for two |
| A lambda's Class, and `Cell<T>`, are generic in generic code | a closure's captures have the instance's types |
| No generic base Classes, and no Static members in generic types, yet; see the Deferred work in [milestones.md](milestones.md) | each needs a design of its own |
| Constraints are checked at each call, `New`, and type written with type arguments; a constrained `T` has its Interfaces' Methods, Properties, Statics through `T.Zero()`, and Operators | errors point at the use that doesn't meet them, and generic code reads like the code it stands for |
| A conditional Method, whose Where line constrains its type's type parameter, isn't in the Method table, so a Class extending one of its instances can't override it, or declare a Method of its name and parameters (M5 step 3) | only some instances have it, so a table slot would be empty for the others, as a generic Method has no slot; a second Method of one name and types is one no call could tell apart |

## Interfaces

| Decision | Why |
|---|---|
| An Interface's Method that's only its first line is required, and one with a body is a default, which a type without its own gets as a Method | a default becomes a Method like any other, which a Class extending it can override |
| An Interface is a type only when it needs no Statics or Operators and doesn't use Self in its members' types; the rest are only constraints | only those can be called on an object whose Class isn't known |
| An Interface's value is a Class's object, and a call goes through a table its Class has for the Interface, which the runtime finds in the Class's list | the value is the object's own reference, so converting it costs nothing and `Is` and `As` work as for Classes; a cache can make the search faster later |
| A Struct implements Interfaces only for generic code, which never boxes it | a Struct stays a value, with no hidden objects |
| A Class extending one inherits its Interfaces, except those that are only constraints | their Self would be the base Class, not the one extending it |
| A required `ByRef Method` is implemented by a Struct's ByRef Method or a Class's Method; a Property by a Property, with a Set if the Interface's has one | a Class's Methods can always change its fields |
| In generic code, an Interface's member calls the type argument's own: directly for a Struct, through the Method table for a Class | generic code costs what the code it stands for would |
| An Interface's Methods can't throw or have type parameters yet, its Properties have no defaults, and its type parameters have no constraints | each needs a design of its own |
| `==` on an Interface's values is an error; `RefEquals` compares the objects | their Classes' == could differ, so neither one is the answer |
| `Abstract Property`, `Abstract ReadOnly Property`, and `Static Property` work like Abstract and Static Methods | a Property's Get and Set are Methods |
| The built-in Interfaces are FutureBlitz code in std/core/interfaces.fb, which the compiler finds by name | the language's own interfaces read like any other |
| Built-in types implement the built-in Interfaces that fit them, and tuples, `T?`s, and arrays by their elements; a Struct or Class implements what it lists | generic code works on the built-in types without anything written, and a user type says what it is |
| A Struct or Class that lists `Equatable` or `Hashable` without its own `==` or `Hash` gets the built-in one: its fields', or its object's | the common case needs nothing written; the built-in `Hash` only goes with the built-in `==`, so equal values always hash the same |
| `Comparable` needs only `<`, and gives `>`, `<=`, and `>=` as defaults | one comparison to write, which the others can't contradict |
| `Hash` gives a `UInt64`; the runtime mixes and combines hashes | combining them by hand needs wrapping arithmetic, which isn't in the language yet |
| A built-in type has the built-in Interfaces' Methods, like `5.ToString()` | what generic code can call on a `T` works on the type itself too |
| An array's `==`, `Hash`, and text are functions lowering makes for each array type | the loop over elements is written once per type |

## Extend

| Decision | Why |
|---|---|
| `Extend` adds Methods, Static Methods, Properties, Operators, and Interfaces to a type, as if its declaration had them; not Fields, a New, or a Destroy | a type's data and its making stay in one place |
| A generic type is extended with its own type parameters' names, `Extend Box<T>`, for every instance; every array is `Extend T[]` | the names mean what they mean in the type, and one Extend fits every instance |
| What an Extend adds isn't in the Method table: nothing overrides it, and it overrides nothing | an Extend in another file can't change what a Class's objects run |
| A built-in type, Enum, or array gets the Interfaces an Extend lists, but not the built-in ones | those come with it by the rules for built-in types |
| An Extend's Where makes what it adds, and what it lists, conditional on its type parameters | `List<T>` is Printable exactly when its elements are |
| A Class that implements an Interface only through an Extend's Where isn't a value of it yet | each instance's object would need a table of its own, which codegen doesn't make yet |

## Sequences

| Decision | Why |
|---|---|
| Interfaces can be generic, like `Iterator<T>`, and a type implements one instance of each | its members' types are always known from the type alone |
| A call infers a constraint's type arguments from what the type argument implements | `Collect(numbers)` needs none written for `Where S: Iterator<E>` |
| `For ... In` goes over an `Iterator<T>`, whose `ByRef Method Next(): T?` gives each element, then Null | an Iterator is usually a Struct, which a loop steps without making an object; like Swift's and Rust's `next` |
| A value whose `Iterate()` gives an Iterator is gone over by that Iterator, with no Interface for it | an Interface would have to name the Iterator's type, which a Struct's would need; like C#'s `foreach` |
| Over an Iterator, `For a, b In` takes each pair apart; only arrays give an index | `For key, value In map` reads the way it's meant |
| `s.Chars` and `s.Bytes` are new arrays | they index and loop like any array; Iterators that don't copy can come with `std.text` |
| A slice is a new `T[]` with copies of the elements, like C#'s ranges on arrays | a view would see the elements move when the array grows or shrinks |
| `nums: Int...` packs the rest of a call's arguments into a new array, and one array argument is passed as it is | like C#'s `params`, both kinds of call read naturally |

## Errors

| Decision | Why |
|---|---|
| Checked `Throws` + `Try`/`Catch`/`Finally` + `Try`/`Try?` prefixes | explicit, no surprise exceptions |
| `Panic` for bugs | |
| Errors lowered as return values | zero cost when nothing throws |
| `Error` is a Class with a `Message`, in std/core/error.fb; every error's Class extends it | one root for Catch and Throws, and a message every error has |
| `Throws` lists Classes, and each error a call can throw is caught or in the function's `Throws` | the compiler knows what can go wrong where |
| A call that throws needs `Try`, `Try?`, or a Try block around it | every place that can throw is marked |
| `Try` and `Try?` bind like prefix operators | `Try? Parse(s) ?? 0` reads the way it's meant |
| `Try?` catches every error and gives a `T?` | treating a failure as no value takes one word |
| A Catch that an earlier one covers, or that nothing in the body throws, is an error | a Catch that can't run is a mistake |
| A Catch and the Finally start from what was true before the Try | the error can come from any part of the body |
| `Finally` runs on every way out of its Try, and can't throw or leave itself; neither can a Defer's statement | cleanup can't replace the error, or jump away in the middle of leaving |
| An `Override` can't throw more than the Method it overrides | a call through the base handles every error |
| A `New` can throw; its object is released without its `Destroy()`, and a throwing base `New` is called `Try Super.New(...)` | opening or parsing in `New` is normal, and `Destroy()` could read fields `New` didn't set |
| `Destroy` can't throw | it runs at whatever release is last, with no caller to give the error to |
| Top-level code can let errors out: its Defers and Finallys run, then "uncaught Class: Message" and exit code 1 | scripts don't need a Try around everything, and still clean up |
| `Panic(message)` and `Assert(condition, message)` are built-ins; code after a Panic doesn't run, and an Assert narrows | a bug stops the program where it's found |
| Assert is checked in release builds too | code after it relies on its condition, so skipping the check would turn a clear panic into a crash |
| A function that throws takes its caller's `Error?` as a hidden last parameter; every Method in a slot does when the first one throws | errors are return values, and overrides stay callable through the Method table |
| `Task.Wait()`/`Await` **re-throw** the task's error | like C# |

## Concurrency

| Decision | Why |
|---|---|
| Three tools for three jobs: tasks/`Parallel For`, async/await, coroutines | covers all game concurrency needs |
| Data races are compile errors (Sendable, `Shared Class`) | safety; keeps refcounts non-atomic by default |
| Engine APIs `@MainThread`; mutable globals main-thread-only unless `Atomic`/`Mutex` | |
| v1 ships tasks, async, channels, Mutex, Atomic, `Thread.Start`; defers lock-free collections, actors, GPU compute | |
| Strings are `Sendable`, so their refcounts are atomic from M2; class objects stay non-atomic | immutable text is the data most often shared between threads |
| The pool starts its workers when it's first used | a program that never uses it has no threads to start or stop |
| A worker that waits for a job runs only the jobs it started itself meanwhile, newest first, and a Channel wait runs none (changed in M4 step 8) | a job it ran for someone else could wait on a Channel for what this thread would do after it, which would never come |
| Each worker's queue is a deque behind a lock; it takes its newest job, and others steal its oldest | simple and correct first; a lock-free deque can replace it without changing the runtime's API |
| A parallel range hands out a few chunks per thread from a shared counter, and the calling thread takes chunks too | a thread that finishes early takes more, and a small range needs no other thread |
| main waits for the pool's jobs before releasing the Globals | a job may still use a Global, like an Atomic |
| A panic or an uncaught error ends the program with `_Exit`, after flushing, and a second thread's panic waits for the end | exiting normally would destroy what other threads still use, like the pool |
| `Sendable` is an Interface in std/core/interfaces.fb, which the compiler decides from a type's parts | generic code constrains on it like any Interface, and no type has to say it |
| A Struct is Sendable only when its fields all are, so one holding a Class reference isn't (settled from open-questions.md) | a copy of the Struct shares the object, whose refcount isn't atomic |
| A type can list Sendable, or an Interface that extends it, and the compiler checks it | a promise a type makes, which a later field can't break quietly |
| Sendable is only a constraint, but an Interface that extends it can be a type | a value of Sendable alone could do nothing; one of an Interface extending it has its Methods |
| `Atomic<T>` and `Mutex<T>` are built-in types, ATOMIC and MUTEX in the type table, that stay where they're made: a Global, a Static Field, or a Class's Field, or passed ByRef | every thread has to share the one; a copy would be a variable of its own, and a Struct is copied |
| An Atomic holds an integer or a Bool, and its operations are sequentially consistent | the simplest order to reason about; LLVM's atomics do it directly |
| Add, Subtract, and Exchange give what the Atomic held before | like fetch_add, which hands out tickets |
| A Lock block's variable is the Mutex's value in place, like a ByRef parameter | the body changes the shared value, and a lambda can't keep it past the Lock |
| A Mutex lets go on every way out of its Lock, as a Defer runs | an error or a Return can't leave it held |
| Locking a Mutex the thread holds already panics, which the runtime knows from each thread's number | it would wait forever, which is worse to find than a panic |
| The runtime's Mutex is a word that's 0, 1, or 2 (held with waiters), waiting with C++20's atomic wait | its zero is a Mutex no thread holds, so Globals and objects need no setup |
| A Shared Class's fb_class_t says it's shared, and the runtime's retain and release check it | an Interface's value can hold either kind of object, so only the object knows; every retain already goes through the runtime |
| A Shared Class extends only a Shared Class, and only a Shared Class extends it | a variable of one never holds an object that one thread owns |
| A Shared Class's object holds a Weak reference to itself while it lives, and counts far above any real count while its Destroy() runs | another thread's last Weak reference can't free it early, and a Weak read can't bring it back while it goes |
| Work on another thread captures only what can't change, holding a Sendable value: a Const, a parameter, a loop variable, or Self (settled from open-questions.md) | a Local is shared by reference, which another thread would change at the same time |
| Spawn and Thread.Start take a lambda or a Function's name, of no arguments | the closure moves to the other thread; one the program kept would be on two threads |
| A Task or Thread stays on the thread that started it, for now | only that thread takes its result, which may be an object of the work's own |
| A Task's object is of a Class the compiler makes for each Task type, shared, whose Method table's first entry runs the closure and keeps the result | the runtime runs any Task the same way, without knowing T |
| The program waits for every Task and Thread before releasing the Globals | they may still use an Atomic or Mutex Global |
| Thread.Start's work runs on a thread of its own that fb_pool_finish joins, as a job the pool counts | one way to wait for both, and a waiting thread still helps with the pool's jobs |
| The main-thread rules follow what a worker's code can reach, through calls, lambdas, overrides, Interface implementations, and a New's Destroy(), once every body is checked | a Func value or object a worker uses is one its own code made, so that's all it can run |
| A Global or Static Field is the main thread's unless it's an Atomic or a Mutex, and so is a top-level Const that isn't Sendable | the main thread could change one while another thread reads it |
| A Shared Class's Destroy() is checked as work on another thread | whichever thread lets go of the object last runs it |
| The error names the shortest way from the work to the use, with the use labeled | the use can be far from the Spawn that reaches it |
| A Parallel For's body is a closure whose code loops over a chunk of the indexes, which the runtime finds first in its Class's Method table | one call per chunk, not per index, and the closure's captures carry what the body uses |
| A Parallel For's body copies what it uses from outside, even a Local, which it can't change | passes run at once, so a shared variable would be a race; the copies need no cell |
| An array from outside a Parallel For's body is used only through its elements and Count, and changed only at the pass's own index | each pass owns its element, and the array object's refcount is never touched off the calling thread |
| A Parallel For's body that changes an outside array's elements reads that array only at its own index, `a[i]`; one that changes none reads any element (M5 final review) | another pass may be replacing the element it reads, which races on its refcount and gives results that depend on timing; reading one array and writing another is the way to use neighbors |
| Parallel For counts up by 1, with no Step | the runtime's ranges are of consecutive indexes |
| A Channel is a built-in, shared object of the runtime's, with a ring of element bytes that compiled code copies in and out with their references | like an array, the runtime needn't know T, and each Channel type's Class releases what's left |
| A Channel's Receive gives a T?, Null once it's closed and empty, and TryReceive sets a ByRef variable | one value says both whether it got one and what, and For x In ch stops at the Null |
| A Channel waits on the pool's condition, whose generation every send, receive, and close changes | one way to sleep and wake for jobs and Channels alike |
| An Async Function is an LLVM coroutine (switched resume), whose frame holds its allocas across an Await | LLVM does the frame and the splitting; lowering only marks where it suspends |
| Debug builds run globaldce before the coroutine passes | coro-split walks the call graph from what the module shows outside, so an Async Function nothing calls would reach the backend unsplit |
| An Async Function's call makes its Task, which the coroutine takes as its first parameter and finishes, and it keeps references to its parameters while it runs | it goes on after its caller has let go of them |
| The runtime's scheduler resumes a coroutine once its awaited Task is done, on the main thread, when top-level code ends and in every Wait() there | the coroutines' code stays on the main thread, and a Wait there can't block what it waits for |
| A Wait or Await on any Task works the same way: a job's done flag, which an Async Function's Task has without the pool running it | Spawns and Async Functions give the same Task |
| Only a Function can be Async for now, without Throws or ByRef parameters, and Await can't be in a Lock | a Method needs its Self kept, Throws needs a Task that holds the error, and a Lock would stay held across the wait |
| `Task`, `Spawn`, `Channel`, `Mutex`, `Atomic`, `Scheduler`, and `Thread` are built in, as `T[]` is, and backed by the runtime | std/ files can't call the runtime until FFI (M5) |
| NextFrame, Seconds, and RealSeconds give a Task that the scheduler running the code finishes at a tick | Await, Wait, and IsDone work on them as on any Task |
| A coroutine waits on the scheduler that ran its Await, and a Scheduler's Run moves it there, with the coroutines and timers it waits for | an Async call starts on the scheduler running the code, before Run has its Task |
| The main scheduler's time is the real clock's, and a Scheduler's is the sum of its Ticks | pausing one is not ticking it, and scaling it is ticking it by less |
| `MainThread()` gives a Task that's done | coroutine code only runs on the main thread, so there's nowhere to hop from |
| A coroutine that starts waiting during a tick goes on at the next one | a loop that Awaits a done Task can't keep a tick from ending |
| A Scheduler that goes destroys the coroutines waiting on it, which let go of what they hold without running their Defers | a Global Scheduler goes at the end with coroutines mid-wait, which would leak; a release shouldn't run user code |
| Once top-level code ends, the main scheduler runs until no coroutine waits, or none can go on: no Task they wait for is done, no timer is left, and the pool has no work; those are destroyed before the Globals are released, and fb_finish ends it again for coroutines that a Destroy starts while they're released, with the timers' Tasks (M5 final review) | waiting for a Scheduler nothing ticks hung the program at its end, as closing a game mid-cutscene would; a panic there would be worse; running code after the Globals go would reach released objects |
| Code nests at most 1000 deep, counting blocks, operators, postfix steps, and parentheses, which the parser reports once per file; fb, fb_lsp, and the compiler tests get a 64 MiB stack on Windows (M5 final review) | each pass recurses as deep as the code nests, so deeper code crashed the compiler with no message; clang has such limits too, and 1000 is past what code a person writes reaches, while a debug build needs about 2.5 KiB a level |
| Calls and News in generic code that give a type parameter a type holding one, and lead back to it, like Deep<T> calling Deep<T[]>, are an error, found through every call's type arguments (M5 final review) | each set of type arguments is an instance, so lowering would make them without end; Rust stops at a recursion limit there, and a compile-time check names the call instead; types alone make no instance, so Node<Node<T>>? as a Field is fine |
| A Parallel For gives the runtime its first and last index, once the loop variable's type says there are any, and each chunk is a first index and a count, which wrap past an Int64's end; helper jobs share the range, and the caller waits for the chunks, not the helpers (M5 final review) | a To at a type's last value has passes, as an unsigned range past 2^63 does, and a worker busy elsewhere can't stall the loop, or hang it when that work waits for the caller |
| Threads of their own are joined at the next Thread.Start once they're done, and the pool joins the rest when it finishes | a program that starts many over time doesn't keep their handles until it ends |
| Adding or removing a value while a For ... In goes over a std collection panics at the next value (each keeps a count of its changes, which its iterator checks), but for a Pool, whose slots stay put; a Deque's First and Last no longer move values, and a Map's new value for a key isn't a change (M5 final review) | a loop that went on skipped or repeated values silently, or failed with an internal index panic; fail fast as C#, Java, and Python do |
| A Pool keeps whether each slot is used, apart from its value, its Generations are Int64s, and its Handles are ReadOnly, Hashable, and made only by it (M5 final review) | a Pool of a T? holding Null lost track of it; an Int count could overflow; a Public Index let code point a Handle anywhere |
| std.ffi goes through the runtime's fb_mem_* and fb_cstring_length rather than declaring C's malloc, memmove, or strlen (M5 final review) | an Extern Function fixes its C symbol's signature for the whole program, so std's declarations kept a program from declaring those as it needed |
| The runtime keeps the CString copies it made, so their count can't go below 0, and Free of anything else, or of one freed already, panics in every build (M5 final review) | freeing C's own memory with the runtime's free is undefined, and a count of -1 hid it |
| An Async Function's errors go in its Task, whose type lists them, "Task<T> Throws E", and Wait and Await re-throw them each time (M4 step 11) | the call returns before the errors happen, and the type says what waiting for it can throw |
| An Async lambda's code makes its Task and calls a coroutine of its own | a call through a function value works the same whatever the lambda is |
| An Override of an Async Method is Async, and an Interface's Methods can't be Async yet | a call through the base, or an Interface, has to make the Task the same way |
| A member loop in a lambda in generic code gets the fields of each instance's type arguments | each instance of the code already lowers its own copy of the lambda's code |

## Compile time

| Decision | Why |
|---|---|
| `#If` is handled by the lexer, which skips the lines of a branch that isn't taken without lexing them | the spec says inactive code needn't parse, and the parser never sees it |
| The symbols are DEBUG or RELEASE, and the platform's; an #If that tests another gets a warning | a misspelled symbol would quietly be False |
| An attribute goes before a declaration, on its line or the one above; the ones for later milestones are reported as not supported yet | attributes read like modifiers, and long ones fit on a line of their own |
| `@Inline` is LLVM's alwaysinline, and debug builds run the pass that inlines it | the attribute asks for inlining whatever the build |
| `@Deprecated` warns at each use outside the declaration and its type | the deprecated code can still use itself while callers move off it |
| A top-level Const known at compile time can be used anywhere, even above its line; one that something needs early is worked out then | sizes in types need them, and the order of known values shouldn't matter |
| A Const Function runs on MIR: sema lowers it and the interpreter in compiler/src/evaluate.cpp runs it, with its own stack of calls | lowering already says what every construct means, so the interpreter only needs MIR; deep recursion doesn't use the compiler's stack |
| A Const Function takes and gives what a Const holds, calls only Const Functions, and uses no Globals or objects | that's what the compiler can hold and run without the runtime |
| A Const Function that fails while it runs is a compile error at the call, with where it failed; it stops after 10 million steps or 10,000 calls deep, or once its variables hold more than 256 MiB, counted where a value is stored and before a String or fixed array is made (M5 final review: the memory limit) | the spec makes overflow and division by zero at compile time errors, and a loop that never ends can't hang the compiler, nor one that doubles a String exhaust its memory |
| In a declaration's type, a size can't come from a Const Function yet | declarations' types are worked out before Const Functions' bodies are checked |
| A Const type parameter is a positive integer, written as a literal, a Const, or another Const type parameter; calls infer it from fixed arrays' sizes | it's for sizes and counts, which are known when types are made |
| `Attribute Name(params)` declares an attribute, a Struct of its parameters, whose values are known at compile time; `f.Attribute(Name)` gives a `Name?` | reflection reads attributes as ordinary values, and their parameters work like a call's, with defaults and names |
| Reflection is `For Field f: F In T` and `For Method m In T`, which lowering unrolls into a copy of the body for each member | it's code generation without a second language: the body is ordinary code, checked once |
| A For Field's body is checked once, with `F` a type parameter that its Where lines constrain; over a function's own `T`, they're constraints on T's fields that each call checks | errors show up where the loop is written or where it's called, never inside a copy |
| For Method goes over Methods that take nothing and give nothing, which `m.Call(value)` calls | they can all be called the same way; Methods with parameters need a way to pass them, which comes later |

## Collections

| Decision | Why |
|---|---|
| The collections are FutureBlitz code in std/collections/, and `T[]`'s new Methods are an `Extend T[]` | they exercise the language, and the compiler only adds the `{key: value}` literal |
| A Map keeps its entries in an array, with each bucket starting a chain of them and each entry linking to the ones added before and after it; removing one moves the last entry into its place and mends what links to it (M6 step 3) | entries without empty slots need no placeholder for a removed key or value, which generic code can't make, and nothing needs compacting; the links keep the order they were added in through removals |
| A Set is a Map whose values are True | one hash table to get right |
| A Map literal makes a Map, then calls its `Add` for each entry | the literal means what the code it stands for means; a repeated key keeps its last value |
| Stack, Queue, and Deque have their own words (`Push`, `Enqueue`, `AddFirst`), and `Add` too | each reads as what it is, and every collection still has `Add` |
| Taking a value from an empty Stack, Queue, Deque, or PriorityQueue panics | `Count` says whether there is one, and a `T?` would make every use unwrap |
| A Queue drops its taken values once they're half its array, and a Deque is two arrays that take half of each other when one runs out | both are amortized constant time without placeholder slots |
| A Pool's Handles carry their slot's generation | a Handle to a removed value never finds the one that reuses its slot |
| Sema's symbols are a `std::deque` | a reference to one stays valid while checking adds more, like a lambda's parameters in a call's argument |

## Loose ends (M3 step 13)

| Decision | Why |
|---|---|
| Explicit arithmetic is an integer's Methods, `a.WrappingAdd(b)` and `a.CheckedAdd(b)`, which gives a `T?`; MIR tests for overflow with a flag on `binary_t` | reads like the operation it replaces, and LLVM's `with.overflow` intrinsics do the test |
| What implements an Interface's throwing Method gets the error variable, whether it throws or not | every Method in a table is called the same way, without an adapter in between |
| An Interface's generic Methods are called only on type parameters, until M6 step 2, whose generic defaults run on Interface values too | each set of type arguments makes a Method of its own, which a table can't hold |
| `For x In Try items` passes on a throwing Iterate's errors | Try already means "let this go on"; the loop has no call to put it before |
| An Extend of one instance or one array type has the instance's types | `Extend Box<Int>` should let `Value` be an Int, not a T |
| An Extend of one instance adds Operators, found like its Methods, and one that isn't generic beats the type's own for every instance that takes the same types, at a use (through a Class extending the instance too) and in what implements an Interface: the instance gets a conformance of its own to the generic type's Interfaces, with each such Operator the listing sees in place of the type's; a default an Interface gives isn't one, and beats nothing; a Class extending the instance, like `Class Names Extends Box<String>`, or `Kept<T> Extends Box<T>` as `Kept<String>`, has what the Extend adds; a default an Interface it lists gives is the Extend's too, outside the generic Class's Method table, so a Class extending the instance can't override it (settled in M5 step 3) | spec 06 has an Extend's members as if the type declared them, and a function that isn't generic already beats generic ones; generic code with `T: Comparable` must run the `<` a use of `<` runs; a default is only taken when nothing the type has implements the member, so letting it win would replace what the type wrote; the Method table is every instance's, so one instance's additions can't have slots in it |
| An instance's Operator == is what == means for it everywhere, in the Structs, arrays, tuples, and T?s that hold one and in generic code, a Class's T?s too, whether or not flow narrowing knows they hold an object, as for a type's own, and a Class's == is the nearest one among it and the Classes it extends, the instance's before its generic type's at each | == can't mean one thing where it's written and another inside what holds the value |
| The generic type's own members, with an instance's types, implement what an Extend of that instance lists, like Box<T>'s `<` for `Extend Box<Int> Implements Comparable`; an instance keeps what its Extends list when its generic type's fields or Interfaces are filled in again | Box<Int>'s `<` takes two Box<Int>s, which is what Comparable asks of it |
| What an Extend of one instance of a Class adds is checked against what the instance inherits, as an Extend of the Class is: it can't override a base's Method or Property that its code can use, or take such a Field's name | otherwise a call through the instance and one through its base would reach different code without either being an override |
| An Extend of one instance, like `Extend Box<Int> Implements Holder<String>`, can't list another instance of a generic Interface that its generic type gives every instance, as `Class Box<T> Implements Holder<T>` does; conform() counts those, with the instance's type arguments, beside what its base implements (given_interfaces(), M5 step 3) | Box<Int32> would implement Holder<Int32> and Holder<String> at once, and a call through one would run the other's Method with the wrong argument |
| A type that got the built-in Hash keeps the built-in ==: an Operator == it gets after, from an Interface's default, another file's Extend, or an Extend of one of its instances, is an error at its Hashable, once every type has what it gets | Sets and Maps hash the fields and compare with ==, so the two must agree whatever order Interfaces are listed in, and == holds in the whole program |
| A Class that implements an Interface through an Extend's Where gets the table for each instance that meets it, which lowering asks sema's implements() about | lowering makes instances analysis never saw |
| A generic base is an instance in `type_t::base`, and walks over a Class's bases go through each one's definition | inherited members keep the instance's type arguments |
| A generic type's Statics are each instance's globals, made as lowering uses them, and start with what's known at compile time | the instances are only all known once lowering is done |
| Const Functions are declared with the Globals, and while types are declared, one runs only when its code reaches no type whose members are still being declared | a size in a Field's type can come from one, without order mattering |
| A computed Const type argument uses only `+` and `*` | the result is positive whenever the parameters are |
| Reflected Properties and Static Fields have no Set | a Property without a Set or a ReadOnly Static Field can't be told apart for a type parameter |
| A For Method's Where line picks the Methods of a Func type | so `m.Call(value, ...)` can be checked once |
| Each copy of a loop over members has its own closure Classes | a lambda there can use the copy's member |

## Modules, FFI, compile-time

| Decision | Why |
|---|---|
| File = module; `Import`; private by default; no textual include | replaces `Include` |

| A program gets only the library code it uses: a library function once something calls it, and a library Class once the program makes one or tests for it | std/ can grow without every program's MIR and executable growing with it |
| The compiler reads std/ from its source tree (`build_config::std_directory`) for now | there's no install layout yet |
| `project.toml` packages with versioned deps and `[native]` libs; static linking default | single-binary games |
| In-source `Extern "C"` blocks + `@CLayout` + `Callback` + bindgen | replaces `.decls` |
| `Const Function`s evaluated at compile time | |
| `Const` is a read-only value, computed at compile time when possible | one keyword for constants and read-only bindings |

| A `Ptr<T>` points at C data only (numbers, Bool, Enums, CString, Ptr, and fixed arrays and Structs of these), Ptr<Void> at anything; it's a type of its own with one field, Value, so `p.Value` and `p[i]` are places that codegen steps through; Null is its zero and `==` compares addresses; Ptr<Void> converts to and from any Ptr implicitly (M5 step 7) | C's memory holds no references, so Unsafe code can't break refcounting; making Value a field lets assignment, ByRef, and nested fields work as for any place |
| Only Unsafe code dereferences, indexes, steps, converts with As, takes AddressOf, reads a CString, or calls an Unsafe Function; Unsafe is lexical, so a lambda made in Unsafe code is too; an Unsafe Function isn't a function value, and what code calls without saying so (Interface members, Operators, Destroy, overrides of safe Methods) can't be Unsafe (M5 step 7) | spec 08's rule, kept checkable: every call of Unsafe code is written in Unsafe code |
| `??` and `?.` don't take a Ptr, CString, or Callback, which is compared with Null instead; a generic's T? of one is a T? with a flag of its own, so Map.Get of a stored Null Ptr isn't Null (M5 step 7 review) | C's pointers aren't T?s and never narrow, and a generic's "none" has to stay apart from a value it holds |
| AddressOf follows the rules for changing what it points at (no loop variable, ReadOnly Field, or Parallel For outside variable), takes a Struct's Self, and a place through a Ptr is settled before later operands, as a T[]'s is (M5 step 7 review) | a Ptr writes, so it can't be a way around the rules for writes, and spec 03's left-to-right order holds through any reference |
| An Extern Function that gives or sets ByRef what could point into text (a CString, a Ptr to Int8 or UInt8, or a Struct or Ptr holding one) takes no String for a CString; a Ptr<Void> doesn't count (M5 step 7 review) | those are what `char*` results like strchr's are, while a Ptr<Void> is usually an opaque handle, which a String argument like a window's title must still reach |
| SizeOf while types are declared declares the members of what it measures first, so a Struct or Enum declared later is measured whole, and one whose size depends on itself is an error (M5 step 7 review) | declarations don't depend on their order anywhere else, and a size measured from half a type would lay out C's memory wrong |
| Whether an Extern Function takes a String for a CString is settled once every type is declared, and a Ptr parameter whose target could hold a pointer into text counts, as a ByRef one does; a Spawn's work gives no CString or Ptr (M5 step 7 review) | a Struct declared later is still the same Struct, and C writes through `char**` as through ByRef; a pointer from a work's thread can point at its dead Locals |
| Debug builds panic on a Null Ptr's Value or index, at the use; a Null CString's ToString panics in every build (M5 step 7) | the check costs a compare per use, which release builds skip as C does; ToString is a copy anyway |
| SizeOf<T>() is computed in sema from C's natural layout, as an Int64 known at compile time; Mem is FutureBlitz code in std/ffi/mem.fb over calloc, free, memmove, and memset, with CopyText for a CString C can keep (M5 step 7) | sizes are known for a Const or a fixed array's size; Mem needs nothing of the runtime's |
| std.ffi is two modules: mem.fb's Mem is raw memory alone (Alloc, Resize, Free, Copy, Fill, Compare), and cstring.fb's `Extend CString` adds `CString.From(text)`, `Length()`, and `Free()` to the built-in ToString, replacing Mem.CopyText; From is safe and makes the runtime's copy (fb_cstring_new), and every size stays an Int64 (M5) | what works on text belongs to the text's type, where code looks for it; From can't break memory, only leak it, and the runtime's copy puts a leaked one in the leak report; a signed size matches SizeOf, Count, and `p - q`, and a negative one panics where a UInt64 would wrap to a huge size |
| An Enum C gives inside a Struct, by value or ByRef, is checked at the call, through nested Structs and fixed arrays, and a non-@Flags Enum that isn't one of its values panics, naming the Field (M5 step 8 review) | an Enum outside its values breaks an exhaustive Select, so the call where C gave it is where to say so, as for one C gives alone |
| `@CLayout` is a Struct's attribute, checked when every type is declared: C data only, other Structs only when @CLayout too, a Field at least, no type parameters; every Struct an Extern Function sees, by value, ByRef, or through a Ptr or fixed array, is @CLayout (M5 step 8) | the attribute is the program saying a layout is C's, which its Fields' order then has to stay; C has no empty or generic structs |
| By-value Structs follow compiler/src/c_abi.cpp's pure classify() over c_layout(), the layout SizeOf gives too: Win64 passes 1, 2, 4, and 8 bytes as an integer, else a pointer to a copy, and returns through sret; SysV classifies eightbytes into INTEGER and SSE pieces (iN, double, float, <2 x float>), counting the six and eight registers left across the call, and passes the rest byval (align 8) or returns through sret; AAPCS64 passes and returns one to four floats or doubles (an HFA) as one [N x float] or [N x double], any other of 8 bytes or less as an i64 (a result as an integer its size) and up to 16 as [2 x i64], and the rest through a pointer to a copy, or returns it through sret; other targets are an error at the Extern (M5 step 8; AAPCS64 in M6 step 0) | LLVM leaves the C ABI to the front end, and clang's lowering is what C code compiled for these targets expects; an array is how clang asks LLVM for consecutive registers, which LLVM's AArch64 lowering then counts itself, on the stack too; a pure function is unit-tested for each ABI, every one's IR is checked from any machine, and CI runs the C calls on each |
| A Callback's code takes no ByRef parameter, an Enum a Callback gives is checked at the call, and a debug build panics on a Null Callback's call (M5 step 9 review) | C passes values, an Enum from C is checked wherever C gives it, and a Null function pointer is as wrong to call as a Null Ptr is to read |
| The built-in scalar types' names (the numbers, Bool, String, CString) can't be declared, but a type the code declares or imports named Weak, Ptr, Void, Task, Thread, Atomic, Mutex, Channel, or Scheduler is the code's own, in types and calls (M5 final review: Weak too) | the scalars are the language's words; the generic built-ins are names a library or game could want, as Spawn and Print can be a module's own |
| An Extern Function used as a Callback is the C function itself, not a thunk (M5 final review) | it has C's ABI already and nothing of the program's to check, and C code compares function pointers, as an API that registers and removes handlers does |
| An Enum argument C passes a Callback is checked in its thunk, which panics at the Function or lambda when it isn't one of the Enum's values (M5 step 9) | C gives the arguments, so they get the check an Enum C gives back gets, and the code's own calls stay unchecked |
| M5's done-when package, tests/packages/bound, checks in fb-bindgen's output for vecmath.h and calls the C library only through it; a bindgen test makes it again and requires the module after its first lines, which name the target, to match (M5 step 11) | the bindings are really generated, while a build without libclang still builds and runs the package; the comparison is the module's, which x86-64 and AArch64 builds share (M6 step 0), and a target whose C ABI FutureBlitz hasn't skips it, since its Structs don't go by value yet |
| Two @CLayout Structs whose Fields have one name and one C type each, in order, are one C type to an Extern Function's symbol, as C's compatible types are across files, and a symbol declared with other types says which (M5 step 11) | two packages can each hold bindings of one header, as two that use one C library do |
| A Bool C gives, or writes in a Struct or through a Ptr, is C's `bool`, 0 or 1; a byte of another value is undefined, as in C, and isn't made 0 or 1 (M5 step 8 review) | C's own bool can't hold it, so only broken C code writes one; as Rust does, FutureBlitz reads a Bool the cheap way, and normalizing every Bool loaded from memory would cost every program for code that's wrong already |
| fb-bindgen skips a function that passes a struct by value for a target whose C ABI FutureBlitz hasn't, with a comment and a warning (M5 step 11) | the module it writes compiles for its target, where sema refuses a by-value Struct |
| fb-bindgen is a tool of its own next to fb, over libclang's C API, built only where CMake finds libclang; `fb bindgen` runs it with what it's given (M5 step 10) | fb never loads libclang, and a build without it builds everything else |
| bindgen reads a header with -nostdlibinc, libclang's own headers, and after them (-idirafter) the C library's include folders of the C compiler that links programs (not that compiler's own headers), in its default C standard with GNU's extensions and with its version as GCC's (-fgnuc-version), for the build's target or `--target`'s, compared by their normalized architecture, system, and environment; another target gets no host folders, and clang's own headers stand alone (-ffreestanding) (M5 step 10) | long, wchar_t, and enums get the library's sizes, from the headers it was built with; clang's own headers take the place of the compiler's, as GCC's come before the C library's for GCC, so MinGW's limits.h doesn't make USHRT_MAX unsigned; headers that ask `__GNUC__` take GCC's branches; GCC's intrinsics headers aren't clang's to read, and a C23 compiler reads `f()` and `bool` as C23 does; a compiler's own limits, like BITINT_MAXWIDTH, are clang's |
| bindgen keeps C's names, adding '_' to a keyword, a type FutureBlitz writes, or a struct's or enum's name that a function or Const has, and to names alike in one scope (a C name that's a fine name keeps it), and binds a struct only when its layout is its fields' own (M5 step 10) | the names match C's documentation, and a packed or aligned struct would be laid out wrong as @CLayout |
| bindgen's macros are worked out by clang as C sees them after the header, each `__typeof__((NAME)) v = (NAME);` in a file of their own that includes it, twice, the second after a `#line`, with `#ifndef` saying which the header `#undef`s, names no macro starts its names with, and any error, a comma operator, or a warning for what C leaves undefined (overflow, shifts, division by zero) leaving the macro skipped; a body with a statement's tokens, an unmatched bracket, a comma between values, or "::", or that uses a macro that has one, isn't tried; its anonymous enum constants have C's type for each (M5 step 10) | a Const has C's type and value whatever the target's long, C's conversions, or what the macro uses, which an evaluator of its own got wrong; clang recovers from what isn't one number, like `10 20`, with a value C never has, so only a clean reading counts, and one that differs where it's used, like `__LINE__`, has no value; a named enum whose values repeat keeps its integer type, which a function that takes it takes |
| bindgen binds only functions and callbacks of the target's C calling convention (C's, or ms_abi on Win64 and sysv_abi elsewhere, which are the same), and skips the others, like vectorcall or regcall (M5 step 10) | FutureBlitz calls and is called through C's convention only, so another's would pass its arguments in the wrong places |
| bindgen makes a flag enum (`__attribute__((flag_enum))`) Consts of its integer type (M5 step 10) | its values are combined, like `A \| B`, which an Enum's value can't be, so a function that gives one would panic |
| What bindgen can't map is a `// skipped:` comment where it was and a warning, and so is what uses it (M5 step 10) | the module always compiles, and nothing missing goes unnoticed |
| A Callback is a CALLBACK type of C scalars only (by-value Structs wait), made only where one is expected, from a Function's name of exactly its types or a lambda that captures nothing, each through an internal thunk with C's extensions that calls its code (a lambda's with a null closure); its code is a worker's, as C can call it on any thread; only Unsafe code calls one (M5 step 9) | a function pointer can't carry captures, so what C passes as user data does; the thunk gives Bools and small integers the extension C expects, and C's threads are the program's problem only through the M4 rules |
| tests/native/vecmath is the C library the FFI tests link, built by CMake with the C compiler that builds the runtime, for UCRT on MinGW; package tests stage tests/packages in the build folder with it in libs/ (M5 step 6) | programs link UCRT, and mixing C runtimes' headers is what step 6 had to show; staging keeps the source tree clean |
| Extern blocks hold only Functions, declared as C has them: numbers, Bool, Enums, and CString, ByRef for a pointer to one, no generics, Throws, Async, defaults, or varargs, and one signature per C symbol, comparing an Enum as its integer type (M5 step 4) | C's linker has one function per symbol, and C has none of the rest; a pointer to one is what an out-parameter needs |
| A String argument for an Extern Function's CString parameter is a NUL-terminated copy, made right before the call and freed right after it, counted in leak reports, and no other CString takes a String, nor one of a Function that gives a CString or takes one ByRef (M5 step 4) | C mustn't keep it, freeing it at the call works inside `&&`, `?:`, and `?.`, and a CString C hands back could point into the freed copy, as strstr's does |
| An Extern Function can give a String or String?, a copy of C's text made right after the call, with U+FFFD for each byte that doesn't start well-formed UTF-8, Null for NULL, or a panic for a String; a C parameter is a CString, never a String (M5 step 4) | the copy is safe code's own, so text from C needs no Unsafe and can't point into an argument's copy, and a String stays UTF-8 for `.Chars` and the rest; a String parameter would hand C the runtime's String itself |
| An Enum C gives, as a result or through ByRef, is checked to be one of its values, panicking at the call; values go as the target's C ABI wants, extending a Bool except on AArch64 outside Apple's targets, and small integers only on x86-64 outside Windows and on Apple's targets (M5 step 4; AArch64's Bool in M6 step 0) | an Enum holding no member breaks every exhaustive Select; clang leaves small integers alone on Windows and other AArch64 targets, and a Bool too on those AArch64 ones, so a thunk mustn't take one as extended there |
| A built-in's parameter that takes any type, like RefEquals', fits a call worse than one that names its type or a type the argument converts to (M5 step 4) | a program's own RefEquals for its types should be the one its calls reach |
| CString is a built-in type: stored and passed, null (C's NULL) as its zero, and not Printable, Equatable, or Sendable until Unsafe code reads it (M5 step 7) | its text is C's memory, which safe code can't check, and == would compare addresses where a reader expects text |
| Print is std.core's Function over the runtime's fb_print through `Extern "runtime"`, which only std/ can use and which passes values as compiled code holds them; the other built-ins stay built in because the compiler checks and lowers them itself: Sendable, in place, Lock, and the generated Task Classes (M5 step 4) | it's std's way into the runtime for M6's modules too, and a String holding a NUL still prints whole |
| An Extern Function's C symbol can't be empty, one the program defines itself, `main` or one starting with `fb_` or `fb.`, except the runtime's own from std, or one of LLVM's, starting with `llvm.` (M5 step 4) | LLVM would give the second declaration another name, bind it to the program's own function, or take it as an intrinsic |
| Two Interfaces' default Operator ==s on a type, neither refining the other, are an error once, at the type, and == on it is an error everywhere until it has its own (M5 step 3) | == means one thing for a type, in a direct == and inside what holds it; reporting use by use would let Contains and a tuple's == pick one silently |
| std's API is Public: Error with its Message and New, the Interfaces, Iterator, each collection with its Methods and Properties, and the iterator Structs their Iterate()s give, with their Next; their Fields and helpers, like MergeSort, Grow, and Balance, stay Private, but for a Pool Handle's Index, which code can key its own arrays by, while its Generation stays Private | programs use std only through what it means to keep; the hints about std modules a program doesn't load name only their Public declarations |

## Standard library (M6)

Planned 2026-10-20 with the user; the design is in [stdlib.md](stdlib.md#m6s-design).

| Decision | Why |
|---|---|
| All of std in M6, built bottom-up, each step on the last | M10's package manager needs HTTP, TLS, and archives; a programmer shouldn't need FFI for everyday work |
| std's `.fb` files have no platform code; the OS layer is the C++ runtime's, behind `Extern "runtime"` `fb_*` functions that mean the same everywhere | one program, one behavior, one expected output per test on every OS |
| The runtime stands on proven, permissively licensed C libraries, statically linked, each a separate archive so a program links only what it uses; nothing LGPL or GPL | fast to build on, fast at runtime, and nothing in them forces a license on programs |
| libuv is the OS layer: files, sockets, processes, pipes, timers, file watching, the terminal, signals, DNS, and the event loop Async I/O runs on | one API for Windows, Linux, and macOS, IPC included |
| libcurl is the HTTP client, over mbedTLS; the HTTP server and WebSockets are FutureBlitz over std's TCP and TLS | the client's edge cases are curl's job; the server is ours to shape |
| PCRE2 with match limits is the regex engine | what most languages use; a pathological pattern throws instead of hanging |
| TLS trusts the OS's certificate store | company roots and revocations count, as in a browser; reading the store is one of the few necessary platform pieces |
| String positions are UTF-8 byte offsets | Find and Slice are O(1), and a position from Find always slices correctly; slicing mid-character panics |
| Interpolation gets format specifiers, `"{price:.2}"`, checked at compile time, with a `Formattable` Interface | formatting numbers is everyday work, and a checked spec can't be wrong at run time |
| Types can define `Operator []` and `Operator []=` | Map, Grid, Buffer, Deque, and StringBuilder read like arrays: `map["hp"] = 5`, `grid[x, y]` |
| Each area has one Error Class with a `Kind` Enum and its details (`IOError.Kind`, `Path`) | Throws lists stay short, and a Catch can still tell kinds apart |
| `Iterator<T>` gets lazy adapters as default Methods (`Filter`, `Map`, `Take`, ...) | chains don't build an array per step, which matters in per-frame code |
| Math is Float32, right-handed, Y up, -Z forward, column-major, quaternions x y z w, 0..1 depth | the modern majority (glTF, Godot, Bevy, three.js), so assets come in without flipping; Vulkan's depth range |
| A Map or Set keeps insertion order through removals | JSON objects and game state iterate predictably; today a removal moves the last entry into the hole |
| FutureBlitz supports only 64-bit targets (x86-64 and ARM64) | pointers, `size_t`, and `ptrdiff_t` are always 64 bits, so only C's `long` and `wchar_t` vary; `Extern "stdcall"`, which 64-bit Windows ignores, can go |
| Built-in `CLong`, `CULong`, and `CWChar`, sized by the target; each widens to `Int64` or `UInt64` without `As`, and narrowing needs `As` | a hand-written binding is right on every OS, and bindgen's output stops depending on the target for these |
| Safe code reaches native memory through `Buffer<T>`, a Class that owns it at a stable address and frees it when its last reference goes, with bounds-checked `[]` and Slice views that keep it alive; a view of memory C owns is made only in Unsafe code, which promises the memory outlives it | C's buffers reach std.io without copying, and safe code never sees freed memory it didn't promise about |
| `ThreadLocal Global x = ...` gives each thread its own, made on its first use and released when the thread ends | the thread checks know workers may use it, and it's the CPU's own thread-local storage, as fast as a Global |
| Formatting, `ToString`, parsing, and JSON are always invariant: `.` for decimals, `,` for thousands; a `Locale` is only ever explicit | the same program writes the same files on every machine |
| Code after an `Await` on I/O resumes where it started, as Tasks do now: at a Wait, a Scheduler's Tick or Run, or `Flip()` | main-thread code stays on the main thread, so `@MainThread` holds across an Await |
| `@PanicsAtCaller` on a Function or Method passes the call's place as a hidden parameter, so its Panics and Asserts report where it was called; std uses it on what panics on misuse | a panic in std, like popping an empty Stack, points at the program's line, as Rust's `#[track_caller]` does |
| After a build that links bundled C libraries, `fb` prints which ones and their licenses, with a file of each one's notices, its own and those of the code it has from others; shipping them is the programmer's job | the programmer knows what to credit, and fb writes no files of its own beside the program |

| std is batteries included: what Python's standard library and its most common packages cover together, plus std.db (SQLite), std.image, std.algo, std.uuid, std.text.template, std.term, std.events, and XML and YAML; packages are for niche domains (2026-10-21) | a programmer needs FFI only for a C library of their own choosing |
| Every std name needs an Import, std.core's too; the language's own features and the compiler's built-ins don't | a file always says what it depends on |
| `Print(values...)` prints any Printable values, spaced; `Input(prompt)` gives a `String?`; both are std.core's | a first program needs one Import, and `Print(score)` just works |
| Text becomes a number through Static Methods on the number types, `Int.Parse("42")`, giving a `T?` | type `Int.` and see them |
| Ranges are values: `0 Until 10`, `1 To 10`, and `Step`, the For loop's own words | they're stored, passed, and chained with the iterator adapters |
| Throw fills `Error.Place` in debug and release builds, and an uncaught error prints its message, place, and Cause chain | release crash reports say where, at a few bytes per Throw |
| Every value has a debug form from reflection, `"{x:?}"` and `Dump(x)`; Printable stays the form for people | debugging doesn't need a ToString per type |
| A collection's `Filter` and `Map` stay eager and give arrays; `Iterate()`'s adapters are lazy | the common case stays simple, and long chains don't allocate |
| Sorting by key is `SortBy(key)` with `ThenBy` for ties, stable and in place, and `OrderBy` on iterators | multi-key sorts read as what they mean |
| `ArrayView<T>` views part of an array without copying and keeps it alive; `x.AsReadOnly()` gives read-only views; slices stay copies | APIs hand out their lists safely, and hot loops don't copy |
| `Map<K, V>(default: v)` gives the default on `[]` reads without adding it, beside `Get(key, fallback)` and `GetOrAdd` | counters and adjacency lists are one line |
| std.collections has spatial structures (SpatialHash, QuadTree, Octree), Trie, LinkedList, IntervalTree, and Immutable collections that share structure | games' queries, and snapshots that cross threads |
| `s.Length` is the byte count, with `CharCount` and `GraphemeCount` beside; `Char` is a built-in 32-bit code point, which `'a'` makes | Length matches byte positions, and code points aren't confused with numbers |
| std reads and writes UTF-8, UTF-16, UTF-32, ASCII, Latin-1, and Windows-1252, with BOM detection | old files, Blitz-era saves among them, keep their accents |
| Templates are Mustache-style `{{ }}`, with HTML escaping on for .html | logic stays out of templates, and braces don't clash with code |
| The compiler checks regex literals with PCRE2; a Regex type and String shortcuts (`s.Matches`, `s.ReplaceAll`) | a bad pattern is a compile error, and one-offs are one line |
| std.text has diffs, fuzzy matching, Markdown, and Humanize | they're what people otherwise go looking for packages to get |
| `Color` is four linear Float32s and `Color32` four sRGB bytes, converting with the right gamma | math in floats, pixels in bytes, and no gamma bugs |
| Angles are radians everywhere, with `Deg(90)` and `ToDegrees` to convert | every formula and GPU uses radians |
| The default random generator is seeded randomly each run until `SeedRandom(n)`; `Random(seed)` objects always repeat | players see new worlds, and tests and replays can still repeat |
| std.math has fixed-point numbers, curves and splines, polygon geometry, and typed units | lockstep multiplayer, paths, level tools, and safer physics |
| `Int` stays 32 bits on 64-bit targets; byte sizes stay Int64 | half the memory in arrays and structs, and 2 billion is plenty for counts |
| Paths are a `Path` type, which a String converts to | paths don't mix with other text, and plain strings still read naturally |
| Reading splits lines on `\n` and `\r\n`, and writing uses `\n` on every OS unless asked | a file is the same on every machine |
| `Embed`, `EmbedText`, and `EmbedFolder` put files in the program at compile time | single-file tools and games carry their data |
| std.io has Preferences, MappedFile, a virtual file system, atomic writes, and file locks | saves never come out half-written, and paks build on the VFS |
| Durations are `2.Seconds` and `500.Milliseconds`, and the timing built-ins take one | no clash with the built-in `Seconds(n)` |
| std.time has a type for each meaning: Timestamp, Date, TimeOfDay, LocalDateTime, ZonedDateTime | 9:00 in New York can't be confused with 9:00 UTC |
| Command-line options are a Struct with attributes, filled by `Args.Parse<T>()`, over a builder | help and errors come free |
| std.concurrent has Select over Channels, TaskSource, parallel algorithms, and `Lazy<T>` | the concurrency tools the built-ins leave out |
| The default logger prints readable lines to stderr, and `FB_LOG` sets levels by module at run time | logging works before anyone sets it up |
| Events are typed `Event<T>` Fields that hold handlers strongly; `Subscribe(owner, handler)` ties one to an owner held weakly; no global bus | wiring stays easy to follow, and forgotten listeners don't leak |
| Serialization is automatic by compile-time reflection, every Field, Private ones too, with attributes to adjust (replacing spec 13's opt-in @Serialize sketch) | one line saves a game |
| MessagePack is std's binary format, and `@Renamed`, a Field's default, and `OnLoaded` keep old saves loading (step 19; step 17 dropped `@Since` for these) | standard binary, and saves survive a game's changes |
| JSON integers stay exact as Longs | ids and big counts survive a round trip |
| std.data reads `.proto` files at compile time, and `.env` files at run time | protobuf services and server configs without tools |
| std.crypto has password hashing, authenticated encryption, signatures and key exchange, and BLAKE3 | secure saves, logins, and update signing without C |
| std.compress has Tar, XZ, and 7z reading beside the common formats | releases, packages, and asset packs |
| An HTTP server's handlers are Async code on its own loop, with `Workers = n` once they're Sendable-safe | no data races by default, and many connections share one thread |
| Routes are Functions, or attributed Classes registered by reflection | small servers stay small, and big APIs stay organized |
| std.net has reliable UDP for games, LAN discovery, and automatic HTTPS | multiplayer, local lobbies, and public servers out of the box |
| std.db is SQLite with typed queries, transactions, and migrations; no query builder or server databases | SQL stays SQL, and every program has a database |
| std.image has the common codecs, WebP, SVG, and animations, transforms, and drawing with TrueType text | tools and servers work with images, and the engine's 2D shares the code |
| std.term has line widgets and full-screen apps | CLI tools look finished |
| Navigation meshes, game AI, and procedural generation wait for the engine phase; Delaunay and Voronoi are std.algo's | they act on levels and entities, which come later |
| M6 is one milestone of 32 steps | the user's call over splitting it |

## Libraries and packages (M7)

| Decision | Why |
|---|---|
| A project is an `executable` or a `library`; nothing FutureBlitz builds is called from C: no `@Export`, C headers, or C-callable DLLs (replanned with the user, 2026-10-24) | FutureBlitz libraries are for FutureBlitz programs |
| A program's project.toml says for each dependency whether it's built into the executable (embedded, the default) or shipped beside it (`link = "beside"`) | one file to ship by default, and a shared or replaceable library where a game wants one |
| A library beside the executable is the OS's own dynamic library, with its own names and extensions (`<name>.dll`, `lib<name>.so`, `lib<name>.dylib`), built only for FB hosts, with its build recorded as an exported `fb.(build).<name>` (its name, version, and ABI hash, and on Windows its executable); the executable loads and checks each as it starts (the user, 2026-10-25: no custom extensions) | the OS loads it, so debuggers, profilers, and crash dumps see it, and tools that know DLLs know it |
| The executable always has the runtime, and every library beside it uses the executable's (its exports on Windows, `-rdynamic` on Linux, `-undefined dynamic_lookup` on macOS) | one heap, one refcount scheme, one scheduler, and one type registry, and a std-only program stays one file |
| A prebuilt library is one `.fblib` per target and mode, LLVM bitcode under its build and bundled lines (M7 step 2), with its .fbi, which embedding links into the executable and `beside` into its library file | a package ships one binary form, and its user picks |
| `Plugin.Load(path)` loads a library built against a host's interface package, checking its ABI hash (left for later, 2026-10-28) | game mods, built after the game |
| A prebuilt FB library ships an interface file, `.fbi`: its Public declarations, and the bodies of its generic, @Inline, and Const code | callers instantiate generics themselves, and the library can be closed source |
| The ABI is exact-version, checked by a hash in each binary | layouts and Method tables change freely; a stable ABI, like Swift's library evolution, costs much compiler work and some speed |
| C++ is called through C APIs and fb-bindgen, never directly | works with any C++ compiler on every platform |
| A package's native code is prebuilt per target in `native/<target>/`, C++ as DLLs | no C++ compiler on every developer's machine |
| One version of each package per program, semver ranges resolved and pinned in `fb.lock` | modules are named by package, and the exact-version ABI wants one build of each |
| Plugins and loading libraries at run time (`Plugin.Load`, `DynamicLibrary`) aren't in M7; they come later, and a program's libraries are its project.toml's dependencies (the user's call, 2026-10-28) | M7 is the packages a program is built with; run-time loading can be designed when mods need it |
| A library's interface file holds what its users compile against: every Public declaration, the Private and Package ones its generic, @Inline, and Const bodies reach (only those bodies see them), and every Field of the types it shows (spec 11; the user's call, 2026-10-28; every member, from step 1's review) | a caller compiles those bodies, and layouts and For Field must agree |
| The executable loads its beside libraries itself as it starts, before any Global, and they reach it through its exported symbols: -rdynamic on Linux, -undefined dynamic_lookup on macOS, and its import library on Windows, so it keeps the name it was built with (spec 11; the user's call, 2026-10-28) | fb names a missing or mismatched file, and calls stay direct; macOS's -bundle_loader can't build a dylib |
| A beside library's own dependencies that the program doesn't list beside are in the executable, with std, and the library uses them through its exports; this replaces step 0's rule that a package two binaries use has to be beside (spec 11; the user's call, 2026-10-28) | each package is still in one place, and a program needn't list what its libraries use |
| A .fbi is `// fbi <name> <version> <hash>`, then each module after `// module <path> <lines>`; a declaration whose code is in the binary is its first line and `=> ...`, a Global or Static Field `= ...` after its type, and a type the source left out is printed, a type of another module after a hidden `Import <module> As __fbi<N>` (M7 step 1) | FutureBlitz source that the parser reads as it is, each module at the .fbi's own lines, so messages point into it |
| The ABI hash is BLAKE3's, 128 bits, of the build and the .fbi's text, and from step 2 the compiled code (M7 step 1) | std already builds BLAKE3; 128 bits tell builds apart |
| A .fbi keeps every member of each type it shows, and every Extend, Private ones as their first lines, still Private (M7 step 1's review) | a program checks against it as against the source: a Private New stays one, an Interface a Private Method implements stays implemented, an Operator stays the type's, and a Class that extends one can't take a Private Method's name; they're what callers need to check, without their code |
| `@MainThreadOnly("why")`, only in a .fbi, says what analysis found in a prebuilt function's body: that only the main thread can run it, and why, which a Spawn's error then says as it would against the source (M7 step 1's review) | the main-thread rules follow calls into code a .fbi leaves out |
| A Field's default is written in the .fbi as its value, which a program sets as it makes the Field's Struct or Class, as it would with the source; an EmbedText default is its text (M7 step 2, revising step 1's review) | a default is known at compile time, and code that makes an object sets it where it's made |
| The .fblib is `// fblib <name> <version> <hash>`, `// bundled <names>`, and LLVM bitcode, linked into the program's module before it's optimized; std's code, generic instances, the code the .fbi keeps, Classes' fb_class_t's, and Interfaces' records are linkonce_odr in both and one once linked, the library's own code external, and then all of it internal but main (M7 step 2) | one module, one optimizer run, and one copy of std's code and Globals, with the program's own build of what it shares; position-independent objects would need comdats and a second set of std |
| Each of a library's modules has an initializer, `<module>.(init)`, for its Globals, which a program's main calls where it reaches the module, and a releaser that main calls where it lets go of the module's Globals (M7 step 2) | its Globals are set and let go of in the order the source would have them, and its Private Globals stay in its binary |
| A Class's list for the runtime's counts is appended to by each binary and made unique once they're linked (M7 step 2) | a Class only a library uses is counted, and one two binaries share is counted once |
| A program that links a prebuilt library's binary makes its own record of every Class the library's .fbi shows, and every record has its debug form, so the program's, with its own Extends' Interfaces, is the one kept when they merge (M7 step 2's review) | a shared record has to be one in every binary, and LLVM keeps the destination's |
| Every Global and Const of a prebuilt module is its binary's, set by its initializer, and every prebuilt module's initializer is called in the modules' order, one with nothing in its .fbi too (M7 step 2's review) | a Const worked out at run time runs once, and a module of only Private code still sets its Globals |
| A name that two things would share across a binary, which each build numbers in its own order, is an error in a build that links (M7 step 2's review) | `x.y.Z()` from module x's Class y and from module x.y would otherwise call the wrong one |
| A library's binary names its files by their paths in the program, so its hash and panics are the same wherever it's built (M7 step 2's review) | a build is the same build anywhere |
| A hidden Import names one of the library's own modules by its path, and another package's by its dotted name, after a qualifier no name of the module's is; a type whose module has no dotted name is an error to write the type (M7 step 1's review) | any folder or file name works, and the .fbi can't redeclare a name |
| The ABI hash on a .fbi's first line covers the rest of the .fbi, the library's compiled code, the compiler's version, the target, and the mode; an error names both builds' names, versions, and hashes (spec 11, M7 step 0's review) | "one exact build" is what's checked, so a new Private Field can't load silently |
| A project.toml's `type` is `"executable"`, the default with a main file, or `"library"`, the default without; an executable without a main, or a library with `main`, is an error (spec 11, M7 step 0) | a package says what it is, and a mistake is caught where it's made |
| A dynamic native's path leaves out its file's "lib" and extension, `native/{target}/engine`, and a path with them is an error that says what to write; `{target}` goes in static paths too, and any other `{...}` is an error (M7 step 5) | one project.toml for every OS and target |
| Every dynamic native of a program's packages is copied beside the executable on each build, whether the program calls it or not, under the name the executable records: the file's on Windows, the SONAME on Linux (the file's without one), and the install name's file on macOS; on Windows the import library's DLL name isn't read (M7 step 5) | the package needs it, and what's there from before is replaced |
| On Linux each dynamic native links as `-l:<its name beside>` from a folder of the link's own, inside `--push-state,--no-as-needed`, and the executable gets `-rpath $ORIGIN`; on macOS `-rpath @loader_path`; only a program with dynamic natives gets either (M7 step 5, and its review) | the name recorded is the one beside it, with or without a SONAME, and $ORIGIN, a DT_RUNPATH, finds only what the executable itself records |
| fb reads each dynamic native's own header, without loading it: a 64-bit DLL, ELF shared object, or Mach-O dylib for the target's CPU (an arm64 build takes a universal file's arm64 slice, not arm64e), with executables and other CPUs' files named as such (M7 step 5, and its review) | a wrong file is an error when the package is checked, naming the package and the file, not a program that won't start |
| Two files going beside the executable under one name, compared case-folded and NFC-composed through utf8proc, are an error at the second's project.toml line, and so is an executable named as one goes beside it (M7 step 5's review) | on a disk that ignores letter case one would replace the other |
| The stand-in engine's C API has only fixed-size types, so one checked-in copy of fb-bindgen's bindings is every target's, in the package's c/ folder, which `Import engine` leaves out; its errors are a thread-local engine_error() that the FB wrapper throws as EngineError (M7 step 6) | the bindings needn't be made per target, a program sees the wrapper's API, and C++ exceptions never cross a C API |
| The executable links each beside library's bitcode too, with the library's own definitions as declarations, so every shared function, generic instance, and type record the library uses is the executable's, kept with weak_odr; the library's file declares them and defines only its own, exported (M7 step 3) | one copy of each, which every binary uses, so `Is` and refcounts agree without a registry of names |
| An executable calls a beside library through a slot per function, which the loader fills with GetProcAddress or dlsym, and reaches its Globals through accessor functions; the library's file records its build, which the loader checks against the one the executable was built with (M7 step 3) | the OS loads it, and fb, not the OS, names a missing or mismatched file before any code runs |
| A beside library's file exports all of its own code (--export-all-symbols), not dllexport's /export directives, which lld splits at a name's ", "; the executable exports no beside library's own names, so its import library doesn't hide them, and a library beside it links against the import libraries of those before it, in dependency order, which load first, with RTLD_GLOBAL elsewhere (M7 step 3's review) | fb's names have ", " in them, and lld exports no symbol whose `__imp_` name it already has |
| A beside library's static natives are in the executable, as its dependencies are, which the library takes them from; its system libraries link into both, and its dynamic ones go beside it (M7 step 3's review) | a static library's state is one copy, and the program can call the library's Externs |
| A Global of another beside library, and a ThreadLocal of the executable's, are reached from a library's file through `fb.(address)` functions, the executable making one for each ThreadLocal a library uses; and in a build that links, a shared ThreadLocal's initializer is always lowered, so every build's maker is the same (M7 step 3's review) | Windows can't import a ThreadLocal, and the maker the linker keeps may be from a build that didn't use it |
| A beside library's build record is `fb.(build).<name>`, and on Windows names the executable it was built for, which the loader checks (M7 step 3's review) | another library's import library would hide a shared name, and a library built for another executable crashes the program that loads it |
| A library's interface file records each package it was built with, `// uses <name> <version> <build>`, the build a prebuilt one's hash or `source:` and a hash of a source one's files, which its ABI hash covers; a program checks each against its own builds, and recomputes a prebuilt library's hash, of this fb, target, and mode (M7 step 7's review) | a library compiled against another build of a dependency has that build's layouts, and a mode's or a changed file would link silently |
| What an interface file keeps, its kept code reaches by what each name refers to, as analysis resolved it, and only a name it didn't resolve, like a type's in a header, by spelling (M7 step 7's review) | a member's, parameter's, or Local's name would otherwise publish a Private Function of that name |
| A C++ native DLL carries its own C++ runtime and exports only its C API: -static on MinGW, -static-libstdc++ -static-libgcc and a version script on Linux; on macOS the system's libc++ (M7 step 6, and its review) | it runs beside any program with only the OS's libraries, and a program's own C++ runtime can't take over the library's |

## Tooling (M8)

| Decision | Why |
|---|---|
| fb runs its own bundled lld directly, with each target's startup files and libraries, and no C++ driver (the user, 2026-10-29, M8 step 0) | building needs no C++ compiler, and lld reads its arguments as UTF-8, so Windows' code page workarounds go |
| Linux programs link against glibc 2.28's stubs, which fb ships, with the runtime and std's libraries built against them; libstdc++ and libgcc stay static (the user, 2026-10-29) | no libc6-dev needed, and programs run on any distribution since about 2018 |
| Releases go to GitHub Releases as archives with install.sh and install.ps1, and as an MSI and a .pkg; self-update waits for M10's dl.futureblitz.dev (the user, 2026-10-29) | one place to download before the site exists, and installers for people who expect them |
| Releases are unsigned for now (the user, 2026-10-29) | the install scripts' downloads aren't stopped by Gatekeeper or SmartScreen, and signing needs paid accounts |
| Stack traces come from a table of FB names, files, and lines the compiler writes into every binary, debug and release (the user, 2026-10-29) | the same on every OS, and a player's crash names its lines with no debug files shipped |
| VS Code debugs through CodeLLDB on every OS, with a formatter script of fb's; Windows debug builds carry DWARF and a PDB (the user, 2026-10-29) | CodeLLDB bundles its own lldb, so there's nothing else to install and one set of formatters |
| No build makes tail calls, release builds too (the user, 2026-10-29, M8 step 3) | a release trace keeps every caller, as Go's do, at a small cost; deep tail recursion uses stack as it does in debug builds |
| An uncaught error's trace is the stack at its first Throw, kept beside the error until it's released (the user, 2026-10-29, M8 step 3) | simple, and it shows where the error began; a throw costs about 2.35 µs instead of 0.88 µs, 12 frames deep |
| The program tests and verify.py compare a panic's trace only for programs whose names say "trace" (M8 step 3) | a trace names std's lines, so every other .out file would change with each edit to std |
| Tests are `@Test` Functions anywhere in a package, left out of builds, and a tests/ folder; `Expect` is built in; one process runs them in parallel, started again after a panic (the user, 2026-10-29) | tests reach a file's Private names, and a run is fast but survives a panicking test |
| std.test's `Expect`, `ExpectThrows`, `Fail`, and `Skip` are compiler built-ins that only a file that imports std.test has, plainly, not through From or As; a file's own Function of their names and types hides them (M8 step 7) | Expect shows a comparison's sides, and ExpectThrows takes an expression, which a Function can't |
| `Fail` goes on after failing, as `Expect` does, and `Skip` ends its test as a Return, only in the test's own code (M8 step 7) | a test reports every failure it finds, and a Skip can't end a test from a lambda or a Defer |
| A @Test Function takes no visibility; a tests/ folder's files use the package's dependencies too, and only its Public names (M8 step 7) | as cargo's integration tests do |
| Leaks fail a test, only in debug builds; after a panic, a debug build runs its finished tests again to check their leaks, and Strings aren't any test's (M8 step 7) | release builds don't track objects |
| `fb test` prints each run's results when it ends, in the tests' order; it also tests a lone .fb file; `fb check` leaves a library's tests/ folder out, as `cargo check` does without --tests (M8 step 7) | the output is the same every time |
| A library's binary and interface file leave its tests out but keep the code only they reach (M8 step 7's review) | programs' instances of a library's generic code can call its Private Functions, so all of them are exported |
| `///` doc comments are Markdown, Rust's way, with `[Name]` links (the user, 2026-10-29) | plain to write and read, and the site renders Markdown already |

## Tooling and process

| Decision | Why |
|---|---|
| C++23, CMake, FetchContent, LLVM + lld | |
| LLVM through its **C API**, linked dynamically (`LLVM-C.dll`, `libLLVM`) | stable ABI; works with the MinGW toolchain and the official Windows installer |
| A small **MIR** between the AST and LLVM IR, from M1 | strings already need scope-based releases; lowering is testable without LLVM |
| M1 links through the C++ compiler that built the runtime, with `lld`, statically | it finds the C runtime; a self-contained toolchain comes later |
| End-to-end tests are `.fb` programs with their expected output | checks the whole pipeline, including the runtime |
| The CLI is `fb`: `fb build`, `fb run`, and `fb check` in M1 | short to type, like `go` and `zig` |

| Color with `--color auto\|always\|never`; `auto` follows the terminal and `NO_COLOR` | readable output that still pipes cleanly |
| Exit codes: 0 success, 1 compile errors, 2 bad usage; `fb run` passes the program's code through | scripts and CI can tell what went wrong |
